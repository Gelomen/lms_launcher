# 变更：GPU 卡片首帧去掉 "…" 占位（消除启动时标签/数值跳位）

日期：2026-09-10
状态：已实施（npm test 353 全绿；npm run build 通过；待用户真机目检首帧）
关联规格：docs/superpowers/specs/2026-09-09-gpu-card-design.md §5.1

## 背景与用户诉求

用户报告（附两张截图）：刚启动应用、GPU 数据尚未到达时（"…" 占位态），
四格信息的位置与数据到达后的位置不一致——占位态下 "…" 靠近卡片左右边缘，
数据到达后同一四格的标签/数值明显向内收缩，标签与数值发生水平跳位。

## 根因

- 占位态由 `.gpu-body :class="{ 'gpu-body--nav': multi }"` 之外的默认布局渲染：
  首帧前 `gpus === null` → `multi === false` → 内容区**没有** 32px 按钮让位。
- 数据到达且判定多卡（本机双 LUID）→ `multi === true` →
  `.gpu-body--nav { padding: 0 32px }` 生效，内容区左右各收窄 32px，
  四格网格整体向内移动 32px——占位态与数据态的标签/数值位置因此不一致。
- 该跳位在单卡机器上不会触发（multi 恒 false），但多卡机器上 100% 复现；
  且「占位时预留给位」无法同时满足单卡/多卡两态（单卡预留给位会导致
  单卡数据到达时反向跳位 + 内容区永久窄 64px）。

## 方案（用户确认）

首帧数据到达前卡片主体**留空**（仅保留「GPU 信息」标题），数据到达后一次性
渲染完整内容（层内标题行 + 四格 + 底部圆点）。布局永远只有一种
（由 multi 唯一决定），彻底消除跳位。

- 代价：启动后约 2 秒（首个 gpu-stats 推送到达前）卡片主体为空，
  由「GPU 信息」标题 + 卡片容器提供视觉锚点；可接受（用户已确认选型）。
- 备选（未采用）：占位态预留给位——单卡机器反向跳位 + 单卡内容区永久
  收窄 64px，被否决。

改动量：
- src/modules/GpuModule.vue：删除 ``<template v-else>`` 占位分支（14 行 → 注释 3 行）；
  JS 逻辑、动画、槽位不变量零改动。
- src/modules/GpuModule.test.ts：首帧用例断言改为「无标题/无四格/无圆点/无按钮」；
  文件头注释同步。
- src/App.test.ts：挂载契约用例首帧断言同步（.gpu-title 不存在）。
- src/style.css 零改动（.gpu-body--nav 让位逻辑保持，多卡数据态仍需要它）。
