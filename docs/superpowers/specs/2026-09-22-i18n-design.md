# LMS 启动器多语言（i18n）设计与分片规格

**日期：** 2026-09-22
**分支：** feat/i18n
**状态：** 已定稿，S0 已落地（2026-09-22），S1–S11 推进中
**性质：** 架构级设计总纲 + 分片卡表；本文件同时充当 Slice 0（基座 + 设置语言切换）的规格

> 本文件是 i18n 全部后续工作的**设计权威**。分片实现或计划与本文件冲突时，以本文件为准。

---

## 1. 目标与非目标

### 1.1 目标

- 支持中文（zh）与英文（en）两种语言。
- 默认跟随系统语言（zh 系 → 中文，其余 → 英文）；用户在设置里手动选择后以选择为准，并持久化。
- 切换入口：设置弹窗；切换后**立即生效**（渲染端响应式 + 主进程重建托盘菜单）。
- 覆盖范围：顶栏、各卡片、各弹窗、tooltip、aria-label、placeholder、动态状态提示、校验提示、日志区（主进程硬编码 sys 行）、任务栏右键菜单、错误消息后缀。

### 1.2 非目标 / 不译边界（强制）

1. **llama-server 原生 stdout/stderr 输出保持原文**（英文，不可译）。
2. llama.cpp release body 解析出的**版本选项 label**（如 `Windows x64 (CPU)`）不译。
3. **固定前缀不译**：`[lms_launcher]`、`MISSING:`、`VALIDATION:`、`YAML:`、`PROC:`、`STATE:`。
4. **专名与单位不译**：`LMS Launcher`、`llama-server`、`llama.cpp`、`GGUF`、`VRAM`、`GB`、`GPU`、参数 flag 第一行。
5. **数据/技术标识不译**：参数 key、选项值（`q4_0`/`auto` 等）、config id、文件路径、版本号。
6. 不引入第三方 i18n 依赖；不改渲染端既有视觉与交互（语言切换 UI 除外）。
7. 已产生的日志/错误不回改（切换语言不重写历史行）。

## 3. 架构与跨切片不变量

### 3.1 词典与翻译 API

- 词典文件：`src-main/i18n/dict.ts`（`as const`，zh/en 两棵**扁平** key→string 映射）。
  - 单一真源。主进程原生 import；渲染端沿用跨目录相对 import 先例（`App.vue` 已引 `../src-main/icon.ico?url`），**不动** rootDir / resolveJsonModule / electron-builder。
- 纯函数（双端共用）：`translate(table, key, params?): string`
  - 占位符语法 `{name}`，替换规则 `/\{(\w+)\}/g`；缺失参数保留原样 `{name}`。
  - 缺失 key：返回 key 本身，并在 dev 下 `console.warn`（不抛错，保证界面不炸）。
- 主进程包装：`src-main/i18n/index.ts`
  - `type Lang = 'zh' | 'en'`
  - 模块级当前语言 + `getLang()` / `applyLang(lang)`（仅主进程内部用，渲染端不直接 import 它）
  - `t(key, params?)` 用主进程当前语言
  - `resolveSystemLang(locale: string): Lang`（`zh*` → zh，其余 → en）
- 渲染端包装：`src/i18n.ts`
  - `const lang = ref<Lang>('zh')`
  - `t(key, params?)` 读 `lang.value`，**响应式**（组件模板/计算属性自动重渲染）
  - `setLang(l)`：`invoke('set_language', l)` + `applyLangLocal(l)`
  - `applyLangLocal(l)`：设 `lang.value` + `document.documentElement.lang = l === 'zh' ? 'zh-CN' : 'en'`

### 3.2 key 命名规范

- 结构：3–4 段，全小写、点分、语义化。前 3 段为 `<scope>.<subject>[.<modifier>]`；第 4 段用于在 modifier 后进一步区分具体的错误/状态（如 `settings.proxy.err.partial` 的 `partial`、`log.launcher.check.found` 的 `found`）。
- scope 白名单（新增需在本文件登记）：
  `common` · `app` · `tray` · `settings` · `dir` · `launch` · `tpl` · `tplModal` · `gpu` · `log` · `update` · `vram` · `err`
- 示例：`common.cancel`、`app.winbar.minimize`、`dir.status.ok`、`tplModal.required.missing`、`update.btn.download`、`log.launcher.check.found`。
- 带插值的 key 用命名占位：`update.btn.downloading` = `{pct}%`（en）/ `下载中 {pct}%`（zh）。

### 3.3 语言状态与双端时序（主进程权威）

- 主进程 `whenReady` 的**第一步**执行 `initI18n()`：读 `lms_launcher.yaml` 的 `language`；缺省时用 `app.getLocale()` 经 `resolveSystemLang` 判定。此后托盘菜单、启动检测日志、更新日志回显全部用该语言。
- IPC（`invoke` 已是通用通道，无需改 preload 白名单；仅在 `src/ipc.ts` 可选加类型化封装）：
  - `get_language` → `'zh' | 'en'`
  - `set_language(lang)` → 主进程写 yaml、更新自身语言、重建托盘菜单（`Menu.buildFromTemplate` + `tray.setContextMenu`）。无返回值。
  - 不引入 `language-changed` 广播（切换只从设置弹窗发起；YAGNI）。若未来出现主进程主动切换，再补事件。
- 渲染端启动时序（避免中文闪烁）：`src/main.ts` 改为
  `const lang = await invoke<Lang>('get_language'); applyLangLocal(lang); createApp(App).mount('#app')`
  —— 先确定语言再挂载。

### 3.4 持久化

- `lms_launcher.yaml` **顶层**新增 `language?: 'zh' | 'en'`。
- **必须同时**修改：`AppConfig` 接口 + `appConfigLoad` 的字段白名单（`src-main/config.ts`，当前只取 llama_dir / vram_total_gb / proxy / update）。漏改会导致每次读配置即丢语言偏好。
- `appConfigSave` 全量重写，天然保留；`saveProxy` / `saveLlamaDir` 用 `...cfg` 展开，无需额外改动。

### 3.5 已产生内容不回改

日志行与错误消息在产生时刻用当时的语言落定；切换语言不重写历史。启动瞬间切语言可能留下少量旧语言行（`did-finish-load` 延迟发送），接受。

### 3.6 英文文案规则

- 七态按钮英文一律最短动词，全部 ≤99.03px，以保持 UpdateModal 的「名称列 = 按钮列」对称（该对称是 2026-09-16 修复中段居中的依据）：
  `Check` / `Checking...` / `Download` / `{pct}%` / `Restart` / `Retry` / `Stop & Update`
- **中文布局冻结**：不重排中文界面。英文如确需，用 `html[lang="en"]` 作用域 CSS 覆盖，禁止改动无 `lang` 限定的既有规则。
- 英文文本不得导致固定像素容器（`style.css` 三列 280/350/300px、`.update-card` 440px、`.confirm-box` 360px、`.vram-dialog` 320px、`.vram-badge` min-width 70px）溢出；必要时该分片单独验收。

### 3.7 测试策略

- `vitest.config.ts` 增加 `setupFiles: ['./src/test-setup.ts']`：每个测试文件开始前把主进程与渲染端当前语言**显式设为 zh**（覆盖「默认跟随系统」——vitest 是 node 环境，无 Electron/navigator system locale，不显式固定会让 280+ 条中文断言的 CI 行为不确定）。
- 新增词典一致性单测：`Object.keys(dict.zh).sort()` 与 `Object.keys(dict.en).sort()` 完全相等；无空值。
- 现有中文断言**不动**；每个分片补 1–2 条 en 冒烟（关键文案切换后正确）。
- 每个分片结束跑 `npm test` 全绿。

## 6. Slice 0 详细设计（本文件展开）

### 6.1 新增文件

- `src-main/i18n/dict.ts`：`export const dict = { zh: {...}, en: {...} } as const`；`export type Lang = 'zh' | 'en'`；`export function translate(...)`。
- `src-main/i18n/index.ts`：主进程语言状态与 `t()`；`resolveSystemLang`。
- `src/i18n.ts`：渲染端响应式 `t()` / `setLang` / `applyLangLocal`。
- `src/test-setup.ts`：测试语言固定。

### 6.2 修改文件

- `src-main/config.ts`：`AppConfig` 加 `language?: 'zh' | 'en'`；`appConfigLoad` 白名单加该字段。
- `src-main/main.ts`：
  - `whenReady` 首行 `initI18n()`；
  - 抽出 `buildTrayMenu()` 供 `createTray()` 与 `set_language` 共用；4 个菜单 label 与 tooltip 占位改 `t('tray.*')` / `t('tray.tooltip.empty')`；
  - 新增 `ipcMain.handle('get_language')` / `('set_language')`，后者写 yaml + 更新语言 + 重建托盘；
  - `src-main/tray-tooltip.ts` 的 `trayTooltipText(name, emptyText)` 改为接收「空占位文案」参数，调用处传 `t('tray.tooltip.empty')`；同步更新 `tray-tooltip.test.ts`。
- `src/ipc.ts`：可选加 `get_language` / `set_language` 的类型化封装（`invoke` 通用，preload 无需改动）。
- `src/main.ts`：await `get_language` → `applyLangLocal` → mount。
- `src/modules/SettingsModal.vue`：新增语言选择控件（复用 `Dropdown`，选项 `中文`/`English`），初始值取 `currentLang`，变更调 `setLang`；弹窗既有文案改 `t()`。
- `vitest.config.ts`：加 `setupFiles`。

### 6.3 语言选择的初始值与回填

- 设置弹窗打开时显示当前语言（来自渲染端 `lang.value`，已由启动时序确定）。
- 变更即调用 `setLang`，不设「保存」按钮——与「立即生效」一致；语言选择本身即持久化。

### 6.4 S0 验收点

1. 设置弹窗可切换 中文 / English，界面立即变化（含 tooltip、aria-label、placeholder）。
2. 托盘右键菜单（打开/检查更新/设置/退出）与托盘 hover 占位文案同步变化。
3. 重启应用后语言保持；删除 yaml 的 `language` 后回到跟随系统。
4. 词典 zh/en key 集合一致的测试通过；`npm test` 全绿。
5. 中文界面与切换前逐像素无回归（仅新增语言控件）。
