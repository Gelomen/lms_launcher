## 任务 1：`key-coverage.test.ts` —— 先让它红

**- [ ] 1. 写失败测试** 新建 `src-main/i18n/key-coverage.test.ts`，两条用例：

1. `全部字面量 t()/hasKey()/errTextOf()/errFromIpc() 的 key 在 zh 与 en 词典中都存在`
   - 扫描目标：`walk('src-main')` + `walk('src')`（`.ts`/`.vue`，排除 `.test.ts`）——比 `no-hardcoded.test.ts` 的 `targets()` 更宽，因为渲染端组件里的 `t()` 同样会把 key 显示到界面上。
   - 匹配：`(?<![A-Za-z0-9_$])(?:t|hasKey)\(\s*'([A-Za-z0-9_.]+)'\s*(?=[,)])` 与 `(?:errTextOf|errFromIpc)\(\s*[^)]*?,\s*'([A-Za-z0-9_.]+)'\s*\)`。两处要点：**字符类必须含大写**（`downloadFailed`、`tplModal.*` 都是大写 key，只写 `[a-z0-9_.]` 会静默漏掉 4 处）；闭合引号后要求 `,` 或 `)`，以排除 `t('tplModal.tip.' + k)` 这类拼接。
   - 失败时收集 `{ file, line, key, inZh, inEn }`，`expect(failures).toEqual([])`（沿用 `no-hardcoded.test.ts:139-148` 的形状，报错直接定位 `file:line`）。

2. `调用点传的占位符名与词典取值里的 {name} 双向一致`
   - 匹配 `t('key', { …`，从 `{` 扫到配对的 `}`（跳过字符串字面量；模板串的 `${}` 自身配对，按深度计数即可），再按**顶层逗号**切分取属性名（`name:` 与 shorthand `name`）；与词典取值里的 `\{([A-Za-z_][A-Za-z0-9_]*)\}` 双向比对，任一侧多/少都记失败。
   - 参数是变量、spread、计算键 → 跳过（规格 H7 的已知局限，注释写明）。key 不在词典时跳过——由用例 1 报，同一处不重复报。

**- [x] 2. 确认红**：`npx vitest run src-main/i18n/key-coverage.test.ts`。实测：用例 1 红，清单恰为 13 处调用点（9 个 key），无误报；用例 2 此时**绿**——占位符比对以词典命中为前提，漂移 key 尚未接上，它无从比对。所以用例 2 的红在任务 2 第 1 步之后出现（见下），两条用例各自见过一次真实的红。

**- [x] 3. 不单独提交**：只含失败测试的提交会留下红 commit，与「每个任务结束时套件绿」的仓库惯例冲突 → 与任务 2 合并为一次提交。此处偏离原计划，记此以免最终审查误判。
