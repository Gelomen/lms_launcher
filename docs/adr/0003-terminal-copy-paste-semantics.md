# 终端页签的复制 / 粘贴语义：智能右键、Ctrl+C 不占用为复制、选区只认鼠标来源

spec #21（票 #22 落地，口径同时约束 #23 / #24 / #25）。用户报的三条症状：划选文字按 Ctrl+C 只发中断、右键把剪贴板里**之前**的内容粘进终端、划完之后界面毫无反应只能猜键。根因链一条：终端库自带的右键处理器会先把光标下的词选中，页签容器随后无条件粘贴；而终端库把 Ctrl+字母一律映射成控制字符，Ctrl+C 永远只会发 ^C。我们决定：把复制与粘贴做成**显式动作**——**智能右键（SmartRightClick）**（有**选区（Selection）**→ 复制并清空选区；无选区 → 粘贴）、键盘 Ctrl+Shift+C 复制、Ctrl+V 与 Ctrl+Shift+V 粘贴（三条入口收敛成同一条粘贴实现）、有选区时工具条出现「怎么复制」的提示（票 #23）；**Ctrl+C 语义完全不动**。提示与右键二态共用同一份「鼠标选区」局部态，永不分歧。

## 四处取舍

### Ctrl+C 不占用为复制

终端库把 Ctrl+字母一律写成控制字符送进 PTY——这是「中断正在跑的训练 / 服务脚本」的全部依赖。把 Ctrl+C 拦成复制（很多桌面应用的默认），正在跑的程序就再也停不掉；用户抱怨的「按 Ctrl+C 剪贴板没东西」的正解是**换一个键**，不是改这个键的语义。复制走 Ctrl+Shift+C（Windows Terminal 等现代终端的既有惯例），钉「Ctrl+C 原样送达终端」的既有用例保留不动。

### 不采用「选择即复制」（copyOnSelect）

- 终端库 5.x 已移除该开关（@xterm/xterm 5.5.0 实测：lib 与 typings 里 `copyOnSelect` 字样已不存在）；
- 更要命的是即便自己实现也会抢剪贴板：查找插件每次命中都会**程序化选中**那个匹配（见下条），「划完自动复制」于是变成「查一次偷一次剪贴板」——user story 12 想要的「查找之后右键仍是粘贴」会当场反转。

### 智能右键以「关掉右键选词」为前提

终端库的右键链路（5.5.0）：mousedown(button=2) → 库自己的处理器按 `rightClickSelectsWord` 先选中光标下的词，**早于**页签容器的 contextmenu。这个选项开着，「无选区」这个条件就永远不成立，智能右键退化成「只复制、永不粘贴」。该选项的默认值按 `isMac` 走（Windows=false、macOS=true）——默认值靠平台，所以构造时**显式写 false** 才是口径；打桩套件钉「组件把 false 递进构造参数」，真库那条 seam 钉「这个名字是真库认得的开关」（坐标级选词行为在 happy-dom 复现不了：无布局 → 字格 0×0，见下面「验证缺口」）。

### 选区只认鼠标来源

终端库的「选区变化」事件是鼠标划选与程序化选中**共用**的，而查找插件命中后就是程序化选中（真机契约两条，已由 TerminalTabView.search.test.ts 钉住：真 addon-search 命中会选中匹配；`rightClickSelectsWord` 是真库认得的开关——打桩套件里分辨不出「选项名错拼被静默忽略」）。所以查找动作那一拍回来的选区变化用同步标志排除，一律算「不是选区」；复位的四条路：清空终端、清空查找、右键复制完成、组件卸载。「鼠标选区」这一份同时决定右键二态与工具条提示（票 #23），两者永不各说一套（user story 23）。

## Consequences

- 术语表从此钉死两条：**选区（Selection）**（查找高亮不是它）、**智能右键（SmartRightClick）**（右键不再是「粘贴」的同义词）。下一个改动若想把右键改回「永远粘贴」或把 Ctrl+C 改成复制，与本页冲突，须明确重开。
- 剪贴板仍走主进程既有通道（读 / 写），不新增 IPC 通道——file:// 下剪贴板不可靠的老问题不得回来（user story 22）。
- 粘贴自此**只有一条实现路径**：Ctrl+V / Ctrl+Shift+V / 无选区右键三条入口共用，票 #25 的多行二次确认只加在那一条上，不各入口写一遍。
- 验证缺口如实登记：happy-dom 无布局（字格 0×0），「真右键选不选词」的坐标级行为不可复现——组件缝钉构造参数、真库缝钉开关被认得，两态的实际行为由票 #26 真机读数②③⑤钉。
