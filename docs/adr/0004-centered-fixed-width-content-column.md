# 界面布局：内容列定宽并水平居中，四列等宽、按三档拆行，日志卡宽度恒等于内容宽度

上区四列卡片的宽度在「2026-10-13-grid-fill-width」§7 定成四个**各不相同**的绝对定宽（280 / 350 / 380 / 330，四列之和 + 3×间距正好填满默认窗口的可用宽度，「不留空」在那时是一条算术测试门），并且明确写下「窗口比默认宽时，富余留在 GPU 卡右侧」。窗口一放大，右侧就出现一大片空白（2560 宽时每侧约 580px），用户判为难看；同时日志卡今天独自撑满可用宽度，「日志卡与上方卡片左右缘对齐」这条契约只在默认窗口那一格成立。我们决定：把上区卡片与日志卡合成一条**内容列（ContentColumn）**，整条**水平居中**，窗口比它宽时富余按左右均分；四列改成**等宽**（335px，四列档的内容宽度仍是 1376，那道算术门等价保留）；窗口变窄时按 **4 → 3 → 2 列三档拆行**，每行正好容纳 N 张卡片，**任何一张卡片自己的宽高都不随窗口变**；**日志卡（LogCard）的宽度恒等于内容宽度（ContentWidth）**，绝不单独随窗口放大。

## Considered Options

- **居中写成 `align-items: center` / `justify-content: center`** —— 否：内容比窗口宽时居中的那一半会跑到裁切边界左边，**左缘永远滚不回来**（窄窗口 / 日后把 `minWidth` 调小时的死角）。只用 `margin-inline: auto`：富余为正时才吸，为负时自动退化成贴左，左缘始终可达。
- **让某一列吸收富余（GPU 卡变宽）或把列宽改成 `fr` / `minmax`** —— 否：§7 里「不用 fr/minmax、全部定宽」那一半是有意的（卡片内的行宽预算、省略号截断、tooltip 锚点都按定宽核过），这次只反转「富余留在右侧」那一半。富余一律变留白。
- **列宽随窗口长、到上限再居中（例如 1800）** —— 否：等于把「定宽」整个推翻，宽度契约与各卡截断预算全部重做，收益只有「少一点留白」。
- **日志卡宽度与四列之和各写一遍数字** —— 否：两处硬编码迟早漂移成 1376 / 1377，「等宽」必须是 CSS 自身成立的（列宽与内容宽度同源、内容宽度由每行列数派生），测试只钉它没被绕开。
- **窄窗口维持今天的「整行不缩 + 出横向滚动条」** —— 否：那样日志卡撑满、上区不缩，两者宽度各说各的，对齐契约破得更彻底。改成**拆行**（三档）后，常规区间连横向滚动条都不需要。
- **拆行两档（一行 / 2×2）vs 三档（4 / 3 / 2）** —— 取三档：窗口宽度落在中段（约 1053–1399）时两档只能白白让出 300px 富余。代价是三列档第二行只剩一张卡（GPU 卡），按用户定的**靠左**，与上一行左缘成一条线，不做行内居中。
- **「矮 + 窄」这个角落（两行卡片 + 日志卡下界装不下）怎么保证纵向永不出滚动条** —— 取**抬高主进程 `minHeight`**：值由「两行卡片高 + 日志卡最小高 220px + 顶栏与内边距」反推（约 800，实施时用取证台实测卡片实高再定），让「任何档位都装得下」成为结构性保证。否掉三条替代：CSS 高度门槛（高度不够就不拆行、退回一行 + 横向滚动）会把「窄窗口不再横向滚动」这个收益在角落里吐回去；日志卡不设下界会让终端被压到几乎不可用；「允许纵向滚动」是用户明确不要的（日志卡不允许被顶到视口外靠滚动去找）。

## Consequences

- **反转的是 §7 的一半**：四列各自不同的定宽、「富余留在 GPU 卡右侧」作废；「全部定宽、不用 fr/minmax」保留。那条算术测试门（四列之和 + 3×间距 = 默认窗口可用宽度）不删，改写成「四列等宽 + 内容宽度随**拆行档**派生 + 日志卡宽 ≡ 内容宽度」，并新增一条防退化门：居中的落点必须是 `margin-inline: auto`，禁止 `align-items/justify-content: center`。
- **窗口最小高自此不再是小值**：`minHeight` 从 540 抬到由卡片实高反推的值（约 800），今天那种「540 高的矮窗」没有了；矮分辨率屏（屏高 ≤768）会受影响——这是刻意的，换来的是「纵向永不出滚动条」不需要任何运行时条件判断。
- **卡片宽度连带**：快捷启动 380→335（−45）、模板 350→335、目录 280→335（+55）、GPU 330→335。名字截断的 JS 预算（30）一条不动，兜底仍交给 CSS 省略号（既有口径：「JS 的宽度预算只是第一道」）。终端画布那三轮「出血 / 内距 / 下圆角」的读数是按旧宽度量出来的，宽度一变就要重新读数（真机门）。
  - **补记（2026-10-26）**：那条连带只管到「不溢出」，可「完整名要能在浮层里读到」当时只挂在预算那一刀上（那一刀落下才挂 tooltip）→ 变窄之后「只被样式省略号裁掉」的那一整段名字（快捷启动行汉字 12~16 字）既被裁又没有浮层。口径从此定为：**浮层跟着真正落下的那一刀走**，两处刀都认；预算一条仍不动 —— 这一判据按屏幕实测，卡片列以后再调宽调窄都不用重算。
- **工具条排内顺序变**：`[全屏]` 成为那一行的新最右颗，`[配色]` 退为次右（`margin-left: auto` 仍留在它身上，排内 DOM 顺序仍等于视觉顺序），钉「`[配色]` 是行内最右颗」的门要改写。
- **日志全屏（LogFullscreen）是全局显示态**：切页签保持、不跨启动记忆；上区卡片整体让位但不卸载（状态不丢）。它与拆行档互不相干——全屏时内容列不再由每行列数决定宽度。
- 三档的内容宽度随每行列数派生（四列 1376 / 三列 1029 / 两列 682），断点即「窗口宽 ≥1400 / ≥1053 / ≥706」，而 `minWidth: 760` 保证最窄那一档仍然装得下——常规区间自此不再出现横向滚动条。
- 术语表新增六条：**内容列 / 内容宽度 / 卡片列 / 拆行档 / 日志卡 / 日志全屏**。下一个改动若想把日志卡改回「撑满可用宽度」、把某列改回弹性宽度，或把纵向溢出改成允许滚动，与本页冲突，须明确重开。
- 与 ADR 0001 / 0002 / 0003 不冲突：配色、页签镜像、复制粘贴语义三条一行不动。
