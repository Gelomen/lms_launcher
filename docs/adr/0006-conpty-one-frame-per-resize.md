# 换行列的口径：两个方向同一支 —— xterm 先换行列、尺寸立刻报，一轮整屏重绘落在一个坐标框里

终端页签的画布由两边共同写（ADR 0005 立的口径）：xterm 持缓冲与滚动区，伪控制台（ConPTY 的 pseudoconsole 模式）不存历史、行列一变就从 home 起把它**此刻**那一屏整屏重画一遍。#33 当时为「[全屏] 后输出被裁减」定的是**按方向分流**：行数变大先报尺寸、那轮重绘落地之后才让 xterm 换行列；行数变小照旧先换行列。2026-10-26 #35（用户实机：鼠标按住应用窗口顶部边框不松、上下拖高度 → 画布不停自动填充重复文本，几乎每一条两遍）把这套分流推翻。我们决定：**两个方向同一支**，并把整段尺寸逻辑收敛到一条不变式上 —— **xterm 缓冲的最后 rows 行 == 伪控制台手里那一屏**（rows = 最近报给它的那个行数）。三条硬口径：

- **A** 换行列一律 xterm 先换行列、报尺寸在后，且建页签时向 xterm 声明「对面那个 PTY 是 ConPTY」：构造参数 `windowsPty: { backend: 'conpty' }`（本应用只出 Windows 包，electron-builder.yml:36，页签对面的 PTY 只有一个来源 = 主进程 node-pty 的 `pty.spawn`）。它只翻转一处行为：行数变大时 xterm 在缓冲**底下**补上伪控制台那几行新的空行，而不是按光标行号把滚动缓冲里的历史拉进视口（@xterm/xterm 5.5.0 common/buffer/Buffer.ts:180-183，库自己的理由：conpty reprints the screen with it's view of the world. Once a line enters scrollback for conpty it remains there）。
- **B** 一轮在途（尺寸已报、那轮整屏重绘未落地）**不报新尺寸、不换 xterm 行列**；这一轮收尾（重绘落地后静默一拍 60ms，或上限 250ms 到点 = 它不会来了）再按盒子**当下**的尺寸追一轮。追的判据是「盒子与这一轮**报出去**的尺寸不同」，不是与 xterm 的当前行列比 —— 后者在某一轮 fit 与 propose 永远差一格时会自己转起来。
- **C** 换行列之前把视口贴回缓冲底部（= 视口正好是那一屏的镜像）；这一轮的时长之内不再摆视口，轮末按开始前的位置还回去：我们自己钉的就重钉一次（#33 要的那条「画布下缘是最后一条还有内容的行」），用户自己在翻历史就原样还他那一行（#33 的「不抢位置」不变；他在轮内自己挪了就改记他挪到的那一行，挂在 `term.onScroll`）。

## Considered Options

### #33 的按方向分流（变大先报尺寸、重绘落地后才换行列）

否。它绕得过「历史被那轮重绘盖成空行」，绕不开连续 resize：把换行列推到下一拍 = 两轮重绘叠在同一个旧坐标框里，第二轮把第一轮的落点顶下去一行；再叠上 #33 自己加的「把最后一条还有内容的行钉到画布下缘」（视口停在镜像之上几行），鼠标按着边框时 ResizeObserver 每帧一发（十几毫秒一次），每一轮踩着上一轮 ⇒ 一路滚雪球。取证台 bench7（真 node-pty + 真 pwsh，跑完 ls 之后一格一行连续 resize，读数 `.temp/fs-clip/raw7-drag.chunks.json`）：每一轮 = ESC[?25l ESC[H <它手里此刻 newRows 行，行间 ESC[K CRLF> ESC[cursorRow;34H ESC[?25h，一轮 750~1650B，**没有 ESC[2J**；**变小 = 从顶上掉行**（贴底，与 xterm 同向）、**变大 = 在底下补空行**（贴顶，与 xterm 反向）。

### ConPTY-first（两个方向都先报尺寸、重绘落地后才换 xterm 行列）

否。行数变小的链子确实保住镜像（xterm 换行列时对「光标以下的空行」的 pop 正好消掉伪控制台丢掉顶上行之后重复的那几条尾巴），但变大这一格失败：换完行列才喂字节，xterm 的 resize 走 push ⇒ 镜像之下多出 junk（实测 buffer 长 37→49 = +6 scroll +6 push）。**变大必须 xterm 先换行列**，且 push 出来的那几行空行恰好就是伪控制台补的那几行 —— 这就是口径 A 的来历。

### 只加 windowsPty，不动 #33 的换序

否。drag 门红在 grow 那一格（同样 37→49 那条形状）：windowsPty 只保证「xterm 换行列时不动历史」，它不能把换行列与报尺寸收进同一拍。

### 顺手打开 windowsMode，或把 buildNumber 也报上

否。`buildNumber` 一有值就顺带开两件事：① buildNumber < 21376 时启用 windowsMode 那套换行启发式（CoreTerminal.ts:259-271），而 InputHandler.ts:721-725 明确写着 ConPTY 该关掉它（"windowsMode should be disabled, which is recommended on Windows build 21376 and above"）；② 按 buildNumber 决定列数变化要不要 reflow（Buffer.ts:292-298）。两条都会让重绘的行落点更难算。只报 `backend` 时这两处在 5.5.0 里都保持关闭，即「只翻转 grow 那一条分支」。

### 每一段重绘字节喂进 xterm 之前都再贴一次底

否（本轮实测把这条从注释与代码里撤掉）。字节那一轮的落点是**缓冲底缘**（`ybase`），与视口停在哪（`ydisp`）无关：探针把 `ydisp` 挪到 14，那整屏 ESC[H 仍画在 `baseY=20` 那一段上，缓冲尾巴与那一屏照样对齐（drift 为空）。所以这一贴只剩「把正在翻历史的用户在轮内反复拽到底」的代价，摘掉之后所有门仍绿 —— 不留没有门的分支。

### 给 `term.onScroll` 加一个「程序化滚动」标志位（把贴底 / 重钉 / 还位置那几次从记账里排除）

否（本轮加了、又撤掉）。记账那一支只在 `roundTarget` 非空时走，而我们自己那三次摆视口全落在这一窗口之外：贴底跑在 `armRound` 之前（那一刻 roundTarget 还没立起来），还位置与重钉下缘跑在 `endRound` 把 roundTarget 清空之后。加上标志位 95 格照绿、摘掉标志位也 95 格全绿 —— 没有任何门会红，所以不留没有门的分支。这条门要的三个变异都在记账那三支上（整支摘掉 / 去掉「顺带覆盖 roundWasOurPin」/ 退回「只在没记过时才记」），每个都实测把「轮末还位置」的读数 11 变成 0。

### 把 xterm 光标 park 到视口最后一行，让 shrink 的 pop / scroll 分支听话

未采。光标位置会进喂给 shell 的那条流（用户下一次按键与它的相对位置都会变），代价大于收益；口径 A + C 已经让 shrink 那一格不出重复。

## Consequences

- 「一轮重绘落在一个坐标框里」自此是**尺寸这段唯一的账本**：口径 A/B/C 三条各自都有门，摘掉任一条都有门当场红（口径 A 摘 windowsPty → resize 的 grow / 上限 / 新输出三格红 + 打桩套件的构造参数门红；口径 C 的贴底摘掉 → shrink 那格红，实测缓冲里多出 10 条重复；口径 C 的用户位置记账摘掉 → 拖窗口那一格「轮末还位置」红，而且那支的三个变体各摘各的都红，见上面那条「程序化滚动标志位」）。
- 一条**机理修正**登记在此：`ESC[H` 在主缓冲里的落点是缓冲底缘（`ybase`），不是视口顶（`ydisp`）。此前写在注释里的「重绘从视口第一行起画」不准确（那是把 `ydisp` 当成了绘制锚点），代码与注释已按探针读数改写。不变式仍然成立、仍然是全部账本，只是踩断它的是「行数在错误的一拍变化 / 两轮重绘叠在一个旧框里」，不是视口停在哪。
- 「画布上出现空白」自此多一个来源：**钉本身**。把最后一条有内容的行钉到画布下缘时，两头都要收住 —— 不越过缓冲顶，也不把空行从画布**上缘**翻进来（内容不足一屏时就会翻过界，#34 那一截空白由这条钉自己造出来，门在 clear.test 的 `blankAboveFirstContent = 0`）。新输出到了不是松手回到底部，而是**跟着最新那条内容重钉**：只 `scrollToBottom()` 的话，让位补在缓冲底下那几行空行又回到下缘，新输出看着像落在画布中间。
- 门：新增 `TerminalTabView.drag.test.ts`（真 xterm + 按 bench7 读数写死的伪控制台模型；播种从当时的视口取，否则 t0 的不变式差一行、门假红）4 格 —— 慢拖逐格查不变式 / 快拖不得有任何一条内容两遍且追平盒子 / 一轮在途不收、收尾后追那一格 / 轮内用户翻历史轮末把位置还他。`TerminalTabView.resize.test.ts` 整组重写（8→9 格），其中「上限」那格的语义从「到点才换行列」改成「到点收尾（把视口从镜像上还给画布）」。打桩套件 `TerminalTabView.test.ts` 逐字钉构造参数 `windowsPty: { backend: 'conpty' }`，并钉一份在途不收的接线。
- 验证缺口如实登记：门里的伪控制台是**照实测读数写死的模型**，不是真 ConPTY；「真机上拖窗口不再重复」归 #35 的真机读数门（用户按 issue 里那几步复看），顺带复看 #33 / #34 的门没被这次改动回归掉。 **2026-10-26 补记**：#35 的真机读数门已通过并关闭 —— 六条读数逐条登记在 https://github.com/Gelomen/lms_launcher/issues/35#issuecomment-6420123177（按住顶部边框来回拖不出重复、不出空白段；松手追平盒子且下缘是最后一条有内容的行；拖的过程中还在输出也不乱；先划上看历史则轮末还他那一行）；同批复看 #33 那五步与 #34 那四步都没被这次重写回归，两张票同日收口。本 ADR 那三条口径自此是**已过真机门**的口径。
- 与 ADR 0005 的关系：那条立的「xterm 与伪控制台必须在同一个坐标框里」不动，本 ADR 正是它在**换行列**这一拍上的落实；0005 的 Consequences 里把 #33 称作「换行列的先后」那半句所指的按方向分流口径，由本 ADR 取代。与 0001 / 0002 / 0003 / 0004 无冲突。
