# 终端配色挂在快捷启动条目上，只作用于终端画布

「命令行」页签里的终端用的是 xterm 默认黑底，与日志页签那套浅色界面（`src/style.css` §4.5）不在同一语言里。我们决定：把**六档预设配色**做成**每个 `shell` 快捷启动条目自己的字段**（yaml 里 `terminal_palette`，落盘时显式写；缺键或非法值一律回落 `paper`，不判该条目非法），并且配色只改终端自己那块着色区，界面其余部分仍是浅色主题。

## Considered Options

- **全局一份（照语言设置那样）** —— 否：「这一行长什么样」应当能从条目本身读出来；同一列表里不同条目要不同观感是真实需求（pwsh 与 WSL 混着跑）。
- **整站深色模式（选暗档时界面一起变暗）** —— 否：那要重做 `style.css` 的全部令牌与每个组件的 hover / 禁用 / 滚动条，是另一个数量级的改动。暗底终端坐在浅色界面里是刻意的「另起一块台面」，不是没做全。
- **开放自定义配色（用户自填前景 / 背景 / 16 槽）** —— 否：一旦开放，这套东西就从「六档核过可读性的预设」变成任意着色器，查找高亮、描边、对比度全都要跟着重设计。

## Consequences

- 六个 id（`paper` / `console` / `warm-paper` / `charcoal` / `campbell` / `warm-night`）从此是对外契约，改名要做兼容或迁移；`campbell` 保留 Windows Terminal 默认配色的官方名，将来加第三方预设时名字能直接对上。
- 配色是条目的字段，所以 [复制] 会带走它；条目被删后仍开着的页签沿用创建时的配色快照，不跳变。
- 换档不重建终端：`term.options.theme = { ... }` 整对象赋值即时重绘，PTY 与滚动缓冲不动（真机取证；改 `term.options.theme.background` 这种内部属性不生效）。
