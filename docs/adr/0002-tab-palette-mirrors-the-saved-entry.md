# 页签的配色是条目落盘档的镜像，不是创建那一刻的快照

票 #18（2026-10-23 用户反馈）：在 [编辑] 弹窗里改了 [配色] 并 [保存]（已落盘），该条目正开着的 [终端] 页签仍停在旧档，就地 [重新启动] 也不换，只有关掉页签或窗口重载才跟上。ADR 0001 把页签的配色定成「建页签那一刻取的快照，此后不回查条目当前值（改名、换档都不跳变）」，而用户的直觉是「这条条目的配色 = 这条条目的终端的样子」——「保存了但看不见」不可接受。我们决定：**条目落盘的那一档是唯一真源，[编辑] 弹窗与 [终端] 页签都是它的镜像**——每次刷新只读配置镜像（`ql_list`）之后，把仍在表里的每条终端页签的配色对齐该条目当前的 `terminal_palette`；只有条目已从配置里消失时不再对齐，那块画布因此冻结在最后一档、不回落默认档。

## Consequences

- ADR 0001 的 Consequences 里「改名、换档都不跳变」那半句作废，换成三分口径：
  - **改名**：页签文案仍是创建那一刻那份（不动，修复轮 B · Minor 2 的结论保持）。
  - **换档（条目落盘）**：已开着的页签跟着换（本 ADR 新增，即票 #18）。
  - **条目被删**：页签冻结在最后一档、不回落默认档（ADR 0001 的这半边不动；票 #16 之后只剩「进程还在跑」那一扇窗）。
- 换档的落地路径不变，代价也因此不变：prop 变 → `TerminalTabView` 的 watch → `applyTheme` 整对象换 theme 并重铺查找装饰，**不重建终端**（ADR 0001 末条的真机取证继续成立）→ 进程不重启、屏上历史不丢、查找计数不被抹成 0/0（重铺会重跑一次增量查找，「当前第几个」可能挪一位）。
- 只有**落盘了的**档会反映到那块画布：弹窗里尚未保存的表单值进不了它（hover 预览仍然优先于对齐结果，优先级仍是「本地浮层预览 > 外部弹窗预览 > 条目落盘档」）；读侧对齐本身一条写通道都不发（零 `ql_save` / `ql_set_palette`）。
- 两份镜像**各有各的刷新时刻**，别把它们并成一份，也别嫌其中一次读取多余：
  - **页签**在 `refreshQlConfigs` 的成功分支对齐（票 #18）——与票 #16 的 `pruneOrphanTerminalTabs` 同一处、同一道「只读镜像里查不查得到该 configId」的查表门；`ql_list` 失败时镜像不动、页签也不动，`[重新启动]` 那条路因此不需要特殊处理（它前面必有刷新）。
  - **[编辑] 弹窗**在**开窗那一刻**读（票 #19：`QuickLaunch.openEdit` 先 `await reload()` 再开窗）。窄通道 `ql_set_palette`（页签工具条那颗）不做任何「读侧失效」广播，卡片缓存于是会停在窄通道之前那一档；弹窗拿缓存回填就会出现「选中标是旧的 + 不动色块 [`保存`] 把用户刚选的档写回去」的数据回退（画布 = 新档、yaml = 旧档）。
  没选「落盘后广播刷新」那条：要新增一条给卡片的 reload 通道（prop + watch）并防刷新回环，收益相同、机制更多，而且挡不住配置文件被别处改动。
